# Skill anatomy

[English](README.md) | 日本語

使っているスキルの成り立ちと設計を学ぶための、AIエージェント向けスキルです。

GitHubのURLを渡すと、指示・参照資料・変更履歴を読み解き、作者が向き合った課題、仕組み、設計判断、自作スキルへの応用を日本語Markdownにまとめます。CodexとClaude Codeで使えます。

## はじめる

Node.js 22以上とGitが必要です。

1. スキルをインストールします。導入先のエージェントと適用範囲は、実行時に選べます。

   ```sh
   npx skills add yamazaki-yuki-23/skill-anatomy
   ```

2. エージェントを再起動し、調べたいGitHubのURLを渡します。

   Codexの場合

   ```text
   $skill-anatomy https://github.com/mattpocock/skills
   ```

   Claude Codeの場合

   ```text
   /skill-anatomy https://github.com/mattpocock/skills
   ```

3. 提示された分析方針と保存先を確認し、「OK」と返します。個別分析を順に保存し、最後に全体の設計と学びをまとめます。

リポジトリ全体、個別スキル、複数スキルを含むフォルダを自動判別します。[個別スキルのURL](https://github.com/mattpocock/skills/tree/main/skills/productivity/grill-me)や、`blob/REF/PATH/SKILL.md` のURLも指定できます。

PR・Issueまで調べる場合は、GitHub CLIを導入して `gh auth login` で認証してください。利用できない場合もファイルとコミットの分析は続け、取得できなかった情報を明記します。

## 何を学べるか

お気に入りのスキルを使ううちに、「なぜこの指示でうまく進むのか」「自分ならどう設計するか」が気になることがあります。Skill anatomyはその疑問をソースと履歴から掘り下げるために作りました。

- 作者がどんな課題に向き合い、どの変更で対処したか。
- 指示の順序、確認のタイミング、参照先への分担が、エージェントの判断をどう変えるか。
- その考え方を自分の別の課題に使うなら、どんな条件と指示が必要か。

質問系のスキルなら、たとえば「推奨回答を添える」指示を取り上げます。利用者が回答案の採用・修正から考え始められる構成を説明し、自作の要件整理スキルへ取り入れる場合の指示例まで示します。

「共通手順への分割を詳しく」など、知りたい観点もURLに添えられます。

説明には出典を付け、作者の発言と分析者の読み解きを区別します。動機が分からない部分は、その範囲を明記します。調査対象は指定リポジトリ内のファイル・コミット・PR・Issueです。対象スキルの実行や採点は行いません。

## レポート

分析を実行している作業フォルダに保存します。

```text
reports/<所有者>/<リポジトリ名>/
├── repository-analysis.md      # 全体像、スキル一覧、共通する設計と学び
├── skill-analyses/<パス>.md     # 各スキルの仕組み、経緯、設計判断と応用
└── .state.json                 # 再開の記録
```

解説の構成はスキルごとに選びます。全体分析から個別分析へリンクするため、興味のあるスキルを選んで読めます。

同じURLで再実行すると、未完了分と変更の影響がある分だけ分析します。共有資料やPR・Issueの索引が変わった場合は全件を再調査することがあります。

| オプション | 動作 |
|---|---|
| `--no-confirm` | 今回の分析方針の確認を省く。ツールの権限確認は省かない |
| `--refresh` | 指定範囲をすべて再分析する |

<details>
<summary>保存先と再実行について</summary>

保存先を変える場合は、エージェントを起動する前に設定します。

```sh
export SKILL_ANATOMY_WORKSPACE="$HOME/.local/share/skill-anatomy"
```

同名スキルは元のパスで区別し、削除されたスキルの過去レポートは残します。レポートと `.state.json` は一緒にGitで管理できます。同じリポジトリの分析は並行して実行しないでください。

PRレビューだけの変更など、自動検知できない更新もあります。再調査したい場合は `--refresh` を指定してください。

</details>

## 更新

```sh
npx skills update skill-anatomy
```

上記の方法で導入した場合、分析結果はインストール先の外に保存され、スキルを更新しても残ります。
