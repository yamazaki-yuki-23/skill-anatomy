概要と使い方

git-guardrails-claude-code は、Claude Code が Bash で Git コマンドを実行する直前に、特定の文字列を含む操作を止めるフックを設置するスキルです。危険な操作を会話上の注意だけに委ねず、実行前の補助スクリプトで判定する構成です。ただし、ここで確認できる実装はコマンド文字列の照合であり、Git 操作全般の安全を保証するものではありません。役割と遮断対象

入力は、プロジェクト単位か全プロジェクト共通かという設置範囲と、遮断パターンの追加・削除の希望です。出力は、選んだ範囲の .claude/hooks/block-dangerous-git.sh と settings.json の設定です。Claude Code の PreToolUse はツールの使用直前に呼ぶ仕組みで、この設定では Bash を対象にします。スクリプトは Bash、JSON 抽出用の jq、文字列照合用の grep を使います。依存の実体はコードから確認でき、SKILL.md に jq の導入工程はありません。設置手順・補助コード

仕組みと処理の流れ

本文にある検証入力 tool_input.command = "git push origin main" を追います。これはフックに渡す JSON の例です。今回この入力を実行した結果ではなく、記述された期待値とコードの対応を説明します。検証例

  1. エージェントは、設置先をプロジェクト内かホームディレクトリ配下か利用者に尋ねます。決まった場所へ同梱スクリプトをコピーし、実行権限を付けます。
  2. 選んだ設定ファイルの hooks.PreToolUse に Bash 用の呼び出しを加えます。既存ファイルがある場合は配列へ統合し、他の設定を上書きしません。
  3. 利用者に遮断一覧の変更希望を尋ね、必要ならコピー先のスクリプトを編集します。
  4. フックは標準入力全体を読み、jq で .tool_input.command を取り出します。例の文字列は一覧の git push に一致します。
  5. 一致すると、該当コマンドとパターンを含む BLOCKED メッセージを標準エラーへ出し、終了コード2で終了します。一致しない場合の終点は終了コード0です。

設置の判断と既存設定の統合はエージェントの責務で、毎回の文字列判定はコピーされたコードの責務です。コードは受け取ったコマンドを自分で実行せず、grep の拡張正規表現で照合します。したがって検証例も実際に push する手順ではなく、JSON を渡して応答を確かめる作りです。設定・調整・検証・照合処理

本文の合格条件は「終了コード2」と「標準エラーの BLOCKED 表示」の組です。固定コミットには、このスキルの独立したテストスイートや評価用入力集はありません。この1例から他の綴りや異常な JSON の扱いまで検証済みとは読めません。

設計判断

設置範囲を決めてから設定を変更する

どのプロジェクトに制約を及ぼすかが決まらなければ、設定ファイルの場所も決まりません。確認できる選択肢はプロジェクト単位と全プロジェクト共通の2つです。スキルは利用者の選択を先に求め、その後にコピーと設定追加へ進みます。採用する判断基準は適用範囲で、危険度によってスキル側が設置先を決める構成ではありません。範囲確認

既存の hooks.PreToolUse 配列への統合という指示は、他のフックや設定を残したまま制約を追加する動作を定めています。調整の対象も同梱元ではなくコピー先です。これにより、設置先の利用者が遮断内容を決める形になります。これらは指示から読み取れる役割分担であり、作者が比較検討した全候補の記録ではありません。既存設定と調整

操作の意味ではなく文字列を判定する

実装上の問いは「何をもって遮断対象とするか」です。採用されているのは固定パターンとコマンド全文の一致で、リポジトリの所有者やブランチの状態は判定材料にありません。通常の push も force push も git push で止まります。一方、push --force や reset --hard という git を含まないパターンも併記されています。パターン一覧

この条件の具体的な意味は、Issue #301の git -C /any/repo push という報告で追えます。文字の間にオプションが入ると git push とは一致しません。ただし同じ報告に挙がる全例が同じ理由で通過するとは限らず、reset --hard は独立パターンにも一致します。ここでは報告者の主張とコードの条件を区別します。判定条件の説明であって、今回の再現実行ではありません。

Issue #898は jq 不在時にも言及しています。固定コードは抽出の終了状態を検査せず、一致がなければ0で終わります。作者アカウントの回答は「AIによるトリアージ生成」と明示され、保守を行わず、安全保証として依存しないよう説明しています。提案された構文解析や失敗時遮断は、採用済みの仕様として扱えません。元の文字列方式を選んだ当時の判断基準や、組み込み deny ルールとの比較理由も未確認です。
