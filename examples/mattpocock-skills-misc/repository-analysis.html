概要

今回の対象である misc の4スキルは、Git操作の制約、テストデータの型表現、教材の雛形、コミット前検査を扱う独立した道具です。日常利用しない道具を残しつつ、通常のプラグイン配布と保守から外すという方針でまとめられています。misc の一覧・凍結方針

各スキルは SKILL.md と表示用の agents/openai.yaml を持ち、Git遮断だけが実行用の補助シェルスクリプトを同梱します。必要な環境は一様ではありません。Git遮断は Claude Code と Bash・jq・grep、型表現の移行は TypeScript と shoehorn、教材生成は pnpm と ai-hero-cli、コミット前検査は Husky・lint-staged・Prettier を前提にしています。外部ツールの実装は今回の対象リポジトリ外です。

分析状況：完了 4 / 未完了 0。対象範囲：固定コミットの skills/misc フォルダと、配布・保守・履歴の説明に必要な関連ファイルです。engineering、productivity、in-progress、deprecated 配下の個別スキルは対象外で、リポジトリ全体の機能を網羅する分析ではありません。

スキル同士の関係

この4件の本文には、相互の呼び出しや、あるスキルの成果物を次のスキルへ引き渡す指定はありません。共通フォルダに置かれている理由は処理の連鎖ではなく、作者が保持するものの利用頻度が低いという位置づけです。分類の説明

Git を使うスキルも役割が異なります。git-guardrails-claude-code は実行直前の遮断を設定し、setup-pre-commit はコミット時の確認を設定します。scaffold-exercises は教材生成後のコミットを指示しますが、ほかの2件の導入を前提にしていません。3件を連続した導入手順とみなす根拠はありません。遮断設定・コミット前検査・教材の終点

個別の流れは各分析の「仕組みと処理の流れ」で追えます。型表現の移行と教材生成は外部パッケージを利用する作業指示が中心で、Git遮断は設置後に動く同梱コードがあります。コミット前検査は、生成した設定から外部ツールと対象プロジェクトの scripts を呼ぶ形です。表示用の agents/openai.yaml は4件とも名前と短い説明だけで、連携処理や実行設定は持っていません。

共通する設計

動作の境界を本文の条件で決める

4件とも、何を処理対象とし、何を完成とするかを本文の条件で定めています。ただし条件の種類は異なります。Git遮断は利用者が適用範囲とパターンを選び、型表現の移行はテスト専用という境界と入力意図で関数を選びます。教材生成は計画の種類指定とコードの有無に従い、コミット前検査は既存の設定や scripts の有無に合わせます。

対象動作を分ける条件具体的に変わる行動
Git遮断プロジェクト単位か全体かコピー先と設定ファイルを選ぶ
型表現の移行部分データか意図的な不正値かfromPartial と fromAny を使い分ける
教材生成計画で種類が明示されているか未指定なら explainer、指定時はその種類を作る
コミット前検査既存設定・検査 script があるか設定を保ち、存在しない script の呼び出しを省く

根拠と適用条件の詳説は、Git遮断の設計、型表現の使い分け、教材の既定値、既存環境への適応にまとめています。これらは本文から読める構造上の共通点であり、作者が4件に共通する設計原則として宣言したものではありません。

完成確認は同じ強さの評価を意味しない

各スキルには最後に確認する行動がありますが、確かめる対象が異なります。Git遮断には1つの JSON 入力と終了コード・標準エラーの期待値があり、型表現の移行にはプロジェクトの型検査の指示があります。教材生成では外部 lint に構造を確かめさせ、コミット前検査ではファイル確認、lint-staged 単独実行、最後のコミットを通します。遮断の期待値・移行後の確認・教材の検査・フックの確認

固定ツリーには選択4件の専用評価スイートや保存された実行結果はなく、外部 lint のコードもありません。このため、確認の指示があることを成果全般の保証へ広げられません。Git遮断の未採用 PR に記載されたテスト件数や、Issue 投稿者の修正版の検証結果も、固定コミットの評価結果には含めていません。

保存することと通常配布することを分ける

misc をプラグインに含めないことは、Issue #164 の作者回答で意図的だと確認できます。7月1日の変更は、その扱いを README などにも反映しました。変更の説明によれば、プラグイン定義はこの変更前から misc を含んでおらず、7月に初めて削除したわけではありません。

さらに、作者による PR #1025は、ローカル開発用のリンク生成でも misc を除外し、通常配布しない位置づけと揃えると説明しています。固定コミットのスクリプトにはその除外条件があります。これは新しくリンクする対象の条件であり、すでに存在する古いリンクを削除する処理までは示していません。

凍結方針が述べる理由は、作者が日常的に使わず修正の妥当性を判断できないことと、利用頻度に対して保守コストが高いことです。一方で、そのまま使える人のためにファイルは残します。設計の保持と保守の継続を分ける判断が、今回の4件に共通する現在の位置づけです。
