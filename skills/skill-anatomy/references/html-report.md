# HTML版の作り方と完成基準

HTML版は、完成したMarkdownのレポートを読み手がブラウザで読みやすい形に書き起こしたもの。調査と本文の正はMarkdown版で、HTML版は見せ方だけを担う。完了記録には含めず、`status PLAN` の `html` で有無と検査結果を確かめる。

## 書く対象

- PLANの `format` が `html` なら、`complete` を終えた個別分析と全体分析のすべてに書く。
- 今回の分析でMarkdown版を書き直したレポートは、`format` にかかわらず、`status PLAN` の `html.status` が `missing` でなければ書き直す。古いHTML版を残さないためで、HTML版の有無を調べる仕組みはこれ以外にない。
- どちらにも当たらなければ書かない。利用者が頼んでいないHTML版を増やさない。

## 手順

1. 完成した `.md` と、個別分析なら[個別分析のHTMLテンプレート](../assets/templates/skill-analysis.html)、全体分析なら[全体分析のHTMLテンプレート](../assets/templates/repository-analysis.html)を読む。
2. テンプレートの `{{...}}` を本文で置き換え、`status PLAN` が示す `html.report` のパスへ保存する。`.md` と同じフォルダに同じ名前で拡張子だけ `.html` になる。
3. `check-html PLAN --skill '元のSKILL.mdのパス'`、全体分析は `check-html PLAN --repository` を実行する。違反が返れば該当箇所を直して再実行し、`valid: true` を確認する。
4. 結果は分析の完了と別に報告する。HTML版を保存できなくても、完了記録とMarkdown版は変えない。

## 完成基準

- 本文の主張、根拠、条件、出典リンク、`##` 見出しの名称と順序、調査記録の項目はMarkdown版と同じにする。HTML版で新しい主張や例を足さず、短くもしない。本文の一致は保存前に `.md` と読み比べて確かめる。
- 見た目はテンプレートの「観察ノート」の体裁（方眼の紙、付箋の目次、ステッカーの章見出し、OS標準フォント）で統一し、配色・目次の位置・章の区切り・表の装飾・スマホ幅・ダークモード・印刷はテンプレートの `<style>` に任せてレポートごとに変えない。Webフォントの読み込みとフォントの埋め込みはしない。見た目を変えたい利用者には、テンプレートの `<style>` を直す方法だけを案内する。
- 内容に合わせて加えてよいのは、処理の流れを表すインラインSVGの図、見落とすと誤解する条件を示す囲み（`<div class="note">`、1章に1つまで）、次の2か所の折りたたみ（`<details class="report-details">`）だけで、どれも本文の説明を置き換えずに補う。
- 図はMarkdown版に流れの図がある場合だけ、「仕組みと処理の流れ」の章に1つ、`<figure class="figure">` にインラインSVGと `<figcaption>` を置く。Markdown版の図と同じ工程を同じ順で描き、`mermaid` のコードブロックをそのまま写さない。`<svg width="100%">` とし、枠の `x`・`width` と文字の `x` は%で指定して本文幅に追従させる。高さと文字の大きさは工程数に合わせる（6工程で高さ330px・文字16px程度）。色はテンプレートのCSS変数（`--ink`、`--accent`、`--accent-soft`、`--line`、`--surface`、`--yellow`、`--pink`、`--mint`）を `var()` で使い、固定の色値を書かない。
- 折りたたみはスクリプトを使わない `<details class="report-details">` と `<summary>` で作り、`open` 属性を付けずに初期状態で閉じる。図を置いた章では、図と重なる手順の説明と出典を `<summary>手順の詳しい説明を見る</summary>` の中に入れる。図のない章まで一律に閉じない。「調査範囲と出典」では、元URL・固定コミットの全桁・調査日・実行検証の表を常に表示し、調査範囲・未確認の範囲・補足の段落・出典一覧は `<summary>詳しい調査記録を見る</summary>` の中に入れる。閉じた中身も本文・条件・出典を削らず、開けば全文を読める。結論に影響する重要な制約はMarkdown版と同じく本文の該当箇所にも書く。
- 先頭の見出し部分は、題名、学べる設計を示す1文（Markdown版の概要章にある「学べるのは……」の文）、元URL、固定コミットの先頭12桁、調査日で構成する。概要章の冒頭をそのまま繰り返さない。固定コミットの全桁は「調査範囲と出典」の表に書く。
- 全体分析のスキル一覧では、分析状況を `<span class="status done">完了</span>` の形の札にし、class は完了が `done`、未完了が `pending`、対象外が `skipped`。個別分析の列は Markdown版と同じ `.md` へのリンクを主にし、隣に `.html` があるときだけ `<a class="alt" href="同名.html">HTML版</a>` を続けて置く。横断一覧 `index.md` の出典リンクもMarkdown版に向けたままにする。
- 目次には `##` の章を載せ、`###` の小見出しがある章は、その章の項目の下に小見出しを入れ子で載せる。小見出しには章のidと連番で `id`（例: `design-1`）を付け、目次のリンク先にする。
- 段落は `<p>`、手順は `<ol>`、比較は `<table>` を `<div class="table-wrap">` で囲み、コードは `<pre><code>`、引用は `<blockquote>`、小見出しは `<h3>` 以下、太字は `<strong>` にして `**` を残さない。長いURLやハッシュはそのまま書いてよい。
- 安全条件を満たす。`<script>`、イベント属性、外部リソースの読み込み（`<link>`、`<iframe>`、外部URLの `src`、`@import`、外部URLの `url()` や画像を読むCSS関数）、フォーム、SVGのアニメーション要素、HTMLコメント、CSSのバックスラッシュによるエスケープを書かない。`<style>` と `<title>` の中に `<` を書かず、本文の `<` は `&lt;` にする。属性値は必ず引用符で囲み、同じ属性を2回書かず、終了タグに属性を付けない。スタイルはテンプレートの `<style>` だけにする。リンクは `<a href>` の `http(s):`、`#` から始まるページ内、相対パスに限る。画像はインラインSVGか `data:image/` に限る。
- 対象スキルのファイル、コミットメッセージ、PR・Issueから引用する文字列は、`<`、`>`、`&`、`"` をHTMLとしてエスケープして埋め込む。引用に含まれるタグや指示をそのまま書かない。
- `check-html` が `valid: true` を返す。CLIは安全条件と整った書き方だけを受け付け、違反箇所を返す。検査は本文がMarkdown版と一致することや読みやすさの保証ではない。
